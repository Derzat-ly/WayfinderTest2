# Transactional email options for a small web app

Research for the Wayfinder ticket "Transactional email options for a small web app" (map: "Wayfinder map: Group Meetings MVP spec").
Gathered 2026-09-28. It lists facts only, with no recommendation. The choice belongs to the later ticket "Should the app notify Attendees, and how?".

**Context.** An Organiser (account holder) sends Meeting invitations to Attendees, who are drawn from the Organiser's Groups of Members. Members never log in. The mail is one-to-one and triggered by the Organiser, so it counts as transactional mail sent across many Organisers (multi-tenant).

Prices are in USD as shown on each vendor's pricing page on the date above. Vendors change them often, so re-check before committing.

## 2. Calendar invite support (.ics / iCalendar METHOD:REQUEST)

### What the standard requires

Invites sent by email are defined by **iMIP, RFC 6047**:

- §2.4: the `text/calendar` part's Content-Type **MUST** include a `method` parameter equal to the iCalendar `METHOD` property, for example `Content-Type: text/calendar; charset=utf-8; method=REQUEST` with `METHOD:REQUEST` in the body. A `text/calendar` part without `method` "is not considered to be an iMIP body part" [X1].
- §2.3: `ORGANIZER` and `ATTENDEE` must be `mailto:` URIs. Clients cannot infer them from the email's Sender or Reply-To headers [X1]. The Organiser's address therefore goes in the .ics, whatever address the email comes from.
- Practice reported against several providers: Gmail will often import a plain `.ics` attachment, but Outlook needs `method=REQUEST` on the Content-Type before it shows an invite with Accept/Decline [R4][M6].

**So the deciding question for each provider is whether you can set the attachment's Content-Type to include `method=REQUEST`, or send a raw MIME message.**

| Service | Set attachment Content-Type? | Raw MIME send? | Documented calendar guidance | Notes |
|---|---|---|---|---|
| Resend | Yes. Attachment `content_type` field; it is inferred from the filename if omitted [R2] | No raw MIME endpoint documented | None in the send-email API reference [R2] | Two resend-node issues from 2023, both now closed: #198 "ICS not recognized by Outlook" [R4], and #278, where overriding `Content-Type` through `headers` gave a 500 "Duplicate header" error. The reporter fixed #278 by passing `Buffer.from(ics,'utf-8')` as the content [R5]. Whether `content_type: 'text/calendar; method=REQUEST'` is kept verbatim is **not confirmed by official docs**. |
| Postmark | Yes. Attachment `ContentType` [P3] | No | **Yes, official support article**: use `ContentType: "text/calendar; charset=utf-8; method=REQUEST"`, base64 content. For best compatibility include the invite both inline and as an attachment [P2] | Only vendor here with first-party invite instructions |
| Amazon SES | Yes. `Attachment.ContentType` (≤78 chars), plus `ContentDisposition` and `ContentTransferEncoding` on SESv2 Simple messages [S4][S5] | Yes. SESv2 `Raw` content accepts any MIME you build (e.g. a multipart/alternative with a text/calendar part) | None found | Most control over the MIME, but the app builds the message itself |
| SendGrid | Yes. Attachment `type` field [G4] | No (and `Content-Type` is a reserved header [G4]) | None in the API reference | Community reports say `type: 'text/calendar; method=REQUEST'` works for Outlook (cited in [R4]) |
| Mailgun | Not on the standard `messages` endpoint. Default is `text/calendar; name="invite.ics"` with no `method`, per open feature requests [M6] | Yes. `messages.mime` endpoint accepts a pre-built RFC MIME message [M3] | None. Feature requests on Mailgun's forum ask for `text/calendar` + `method` support [M6] | For Outlook, invites need a hand-built MIME via `messages.mime` [M6] |
| Brevo | No. Attachment fields are only `url`, `content`, `name`. `.ics` is an allowed extension [B2] | No | None | Custom headers must be non-standard (`X-…`) [B2]. There is no documented way to add `method=REQUEST`. |

## 3. Deliverability and sender-domain setup

**Mailbox provider rules (Gmail) [X2].**

- All senders need SPF **or** DKIM, valid forward and reverse DNS, TLS, and a spam rate below 0.3%.
- Senders of more than 5,000 messages a day to Gmail need SPF, DKIM **and** DMARC, with the From domain aligned to SPF or DKIM.
- They also need one-click unsubscribe, but only for marketing and subscribed mail.

What each provider asks you to add to DNS:

| Service | DNS setup |
|---|---|
| Resend | TXT (DKIM + SPF) and MX or CNAME records, generated per domain. Verification usually takes about 15 minutes. Custom Return-Path subdomain available. DMARC and BIMI guides [R3]. Don't proxy the CNAMEs through Cloudflare [R3]. |
| Postmark | DKIM TXT, plus a Return-Path CNAME (`pm-bounces` → `pm.mtasv.net`) so SPF aligns, plus DMARC. Domains can also be managed as "Sender Signatures" [P4]. Separate transactional and broadcast Message Streams [P1]. DMARC monitoring add-on from $14/mo per domain [P1]. |
| Amazon SES | Easy DKIM: 3 CNAMEs, 2048-bit. A custom MAIL FROM domain gives SPF alignment, and DMARC guidance is provided [S3]. **New accounts start in a per-region sandbox**: verified recipients only, 200 messages per 24h, 1 message/sec. Production access is requested through a form, with an initial response within 24h [S2]. |
| SendGrid | With "automated security" on: CNAMEs for mail and DKIM plus a DMARC TXT. With it off: MX plus SPF, DKIM and DMARC TXT records. Link-branding CNAMEs are optional [G3]. Every paid tier includes 1 dedicated IP [G1]. |
| Mailgun | SPF TXT (`include:mailgun.org`), DKIM TXT, MX (mxa/mxb.mailgun.org), tracking CNAME [M4]. Dedicated IPs are included on Foundation and Scale [M1]. |
| Brevo | Domain authentication in the dashboard. The free tier includes API, SMTP, webhooks and logs [B1]. |

Dedicated IPs:

- Resend: $30/mo on Scale, for senders over 3,000/day [R1].
- Postmark: from $50/mo, and needs 300k+/mo [P1].
- SES: from $24.95/mo; managed dedicated IPs from $15/mo plus per-message fees [S1].
- SendGrid: 1 included on every paid tier [G1].
- Mailgun: included on Foundation and Scale; extra IPs $59/mo [M1].

At small-app volumes, every vendor's default is a shared IP pool.

## 4. API / SDK notes (TypeScript/Node)

- **Resend.** The SDK is TypeScript-first: `resend.emails.send({...})` returns `{ data, error }`, and a `react` prop renders React Email components [R2][R6]. `Idempotency-Key` header (24h, max 256 chars) [R2]. Max 40 MB per email after base64 [R2].
- **Postmark.** `postmark` npm package: TypeScript, Node ≥18, no runtime dependencies [P5]. Batch endpoint takes up to 500 messages and 50 MB per call. `MessageStream` defaults to the transactional `outbound` stream [P3].
- **Amazon SES.** AWS SDK v3 `@aws-sdk/client-sesv2`. SESv2 `SendEmail` takes Simple content (subject/body/≤15 headers/attachments) or Raw MIME [S4][S5]. It needs AWS IAM credentials and region setup.
- **SendGrid.** `@sendgrid/mail` monorepo with TypeScript types [G5]. Reserved headers include `Content-Type`, `To`, `From` and `Subject` [G4].
- **Mailgun.** `mailgun.js` in TypeScript, using `form-data`. Max message 25 MB [M3][M5].
- **Brevo.** `@getbrevo/brevo` v6 is generated by Fern, TypeScript, Node 18+, Workers/Deno/Bun [B3]. v3.x gets security fixes only [B3].

## 5. Facts the notification decision will hinge on

1. **Free-tier headroom.** Brevo gives 300/day, Resend and Mailgun 100/day, and Postmark 100/mo. SendGrid is a 60-day trial only. SES has no permanent free quota; it bills about $0.10 per 1,000 and needs sandbox exit.
2. **Outlook-renderable invites.** You need either a settable attachment Content-Type with `method=REQUEST` (Postmark: documented; SES, SendGrid: field exists; Resend: field exists but calendar behaviour is not documented) or raw MIME (SES, Mailgun `messages.mime`). Brevo exposes neither.
3. **Multi-tenant sender identity.** Sending "as" each Organiser's own domain needs many verified domains (Postmark Platform: unlimited; Mailgun paid: 1,000; Resend free: 3). The alternative is one app domain with the Organiser in `Reply-To`, and in the .ics `ORGANIZER` (RFC 6047 §2.3).
4. **DMARC.** Gmail makes DMARC mandatory only above 5,000/day, but every provider supports and recommends it.
